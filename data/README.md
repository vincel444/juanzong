# 测试资料库

这里存放三类评测资料。请只放**已脱敏、可公开用于评测**的文件；原始客户姓名、证件号、账号、联系方式、地址、签章图片等不得入库。

## 目录约定

```text
data/
├─ contract_review/       # 1 份 20–50 页合同 PDF（主场景）
├─ cross_document/        # 同一项目的 5–10 份互相关联文档，PDF 优先
├─ code_qa/               # 几十文件的小型开源项目（保留 LICENSE）
├─ manifest.csv           # 每份文件的页数、字数、来源和脱敏状态
└─ questions/              # 问题集与参考答案要点
```

当前仓库中的 `测试合同-节选.md` 仅用于连通性/回归测试，不计入真实资料库，也不替代 20–50 页合同 PDF。

## 入库流程

1. 将脱敏后的文件放入对应目录，文件名使用稳定、无隐私的信息（如 `project_alpha_payment_agreement_v1.pdf`）。
2. 在 `manifest.csv` 增加一行：文件名、场景、页数、字数、语言、来源、脱敏状态、校验日期。
3. PDF 页码必须能在阅读器中核对；扫描 PDF 需同时提供 OCR 文本或确认解析链路支持 OCR。
4. 为每份资料补 8–10 道问题，写入 `questions/`，并标注问题类型、推荐思考档位和可核查页码。

## 质量门槛

- 合同审阅：正文 20–50 页，页码清晰，至少包含付款、交付、违约、保密、终止/争议解决等条款。
- 跨文档对比：5–10 份文档属于同一项目，至少有 3 处可对比字段（金额/日期/付款/责任等）。
- 代码问答：几十个文件、可离线安装或运行，保留 README、LICENSE 和提交版本信息。
- 不确定的页码或字数不要估填，先写 `待统计`，完成统计后再运行基准。
