# 用户访谈工具包（成员E执行）

> 目的：为初赛 PPT 的「用户痛点 → 用户价值」章节提供真实反馈支撑。
> 时长控制在每人 15 分钟，2 位受访者即可；结果一句话发群里即可，
> 由队长整理进 PPT。**以下模拟纪要仅供格式参考，PPT 必须使用真实访谈结果。**

## 一、目标受访者画像（二选一各找一位）

| 画像 | 特征 | 为什么找 TA |
|---|---|---|
| A. 处理合同/单据的职场人 | HR、行政、财务、采购、法务助理 | 日常读长文档，痛点最真实 |
| B. 高频阅读自由职业者/学生 | 租房签约、兼职协议、论文/项目文档 | 消费级场景，覆盖面广 |

## 二、访谈脚本（5 问，按顺序问，追问不加戏）

1. **现状**：你平时最常遇到需要仔细看的长文档是什么？大概多久一次？
2. **痛点**：最近一次签/审文档，你最担心漏掉什么？当时怎么确认的？
3. **隐私**：这类文档能不能接受上传到网页版 AI 处理？为什么？
4. **体验期望**：如果一个工具回答时能告诉你"这句话来自原文第几页"，
   并把没把握的部分标出来，你觉得对你有用吗？
5. **使用门槛**：你希望它在什么设备上跑？愿意等多久得到答案？

> 记录要点：每个问题记原话（而不是你的总结），原话进 PPT 最有说服力。

## 三、记录模板（复制后填写）

```

1. 现状：
2. 痛点：
3. 隐私：
4. 体验期望：
5. 门槛：
金句（最有说服力的一句原话）：
```

## 四、模拟纪要示例（仅供格式参考，禁止直接进 PPT）

```
受访者编号：01   画像类型：A（行政）   日期：2026-09-19（模拟）
1. 现状：每月要过 2-3 份供应商合同，每份十几页。
2. 痛点：最怕付款节点和违约金条款前后对不上，都是肉眼翻页核对。
3. 隐私：合同有公司报价，网页 AI 绝对不敢用，会违规。
4. 体验期望：有用，现在最烦的就是不知道 AI 说的在原文哪里。
5. 门槛：公司电脑就行，太慢也能接受，比肉眼翻强。
金句：「AI 说得再好，指不出第几页我就不敢信。」
```

## 五、结果去哪

- 发群里一句话 + 模板即可
- 队长会提炼进 PPT「用户价值」页：痛点原话 ↔ 产品特性（离线/溯源/三档速度）一一对应
