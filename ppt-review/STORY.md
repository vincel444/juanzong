### P2｜一句话主张 + 三个数字
**主张**：消费级笔记本，离线装下整卷资料，逐句回查到页码。
三个巨型数字锚点：
- **8 GB** 显存即可跑（1.7B + 4B 双模型同驻 5.5 GB）
- **134 tok/s** 端侧推理速度（1.7B Q4_K_M，GPU 全层卸载）
- **0** 字节数据出设备（飞行模式全程可跑）

role: hero

### P3｜痛点：隐私与效率的二选一
- 用户原话：「公司合同里有报价、账期，网页版 AI 一律不敢用」（模拟访谈）
- 用户原话：「AI 说得再好，指不出第几页我就不敢信」
- 现状：云端方案 → 数据合规风险；本地小模型 → 装不下长文档 / 质量差
- 缺口：**端侧 1M 上下文 + 可验证的引用** 同时成立的产品不存在
role: supporting（左文右图：云端风险 vs 本地方案的对比示意）

### P4｜技术架构：三层分工
```
资料层：PDF/Word/MD 解析 → 整卷装载(≤40万字) → 关键词检索兜底
模型层：1.7B(常驻快答) ─┬─ 轻档 关思考 <1s
                       ├─ 中档 开思考 数秒
                       └─ 路由 ─→ 4B 深档 开思考 → 跨条款审阅
校验层：8-gram 回查原文 → 句子级命中率 → 页码定位 → 未溯源标注
```
role: supporting（架构图为主视觉）

### P5｜三档自适应 + 流式输出
- 三档策略表（档位 / 模型 / 思考 / 时延 / 适用）
- 流式：思考过程与回答逐字上屏，首字时延 < 1s，深档 40s 不再黑屏
- 智能降级：1.7B 思考超限无输出时自动关思考重试（保可用性）
role: supporting

### P6｜溯源校验：凭什么信它（差异化核心）
- 机制：回答逐句切 8-gram → 回查原文索引 → 命中率 → 定位页码
- 三级判定表：✅ 已溯源 / ⚠️ 部分溯源 / ❌ 未溯源
- 真实演示数据（合同样本 13 句）：
  - 合同原文引用 0.50–1.00 → 已溯源，可点页码核验
  - 条款分析 0.29–0.33 → 部分溯源，提示重点看
  - 外部法条/建议 0.00 → 未溯源，明确标出"不是从你资料里来的"
- 口径：**不是"判断模型对不对"，是"把每句话分类，让你 10 秒知道该核查哪几句"**
role: hero（本页是三张表 + 色彩分级的重点展示页）

### P7｜端侧实测：跑得动吗（25 分）
- 技术路线对比表：transformers bf16 vs llama.cpp Q4_K_M
  - 1.7B：3.5 → **134 tok/s**（35–60 倍）
  - 4B：~1 → **63 tok/s**
  - 显存：3.7GB 单模型 → **5.5GB 双模型同驻**
- 硬件：RTX 5060 Laptop 8GB / 驱动 592.27
- 配图：bench_chart.png（左半：路线对比柱状图 + 显存）
role: hero

### P8｜三档时延实测 + 端侧工程细节
- 时延表：轻档 0.4–0.9s / 中档 2.0s（降级兜底）/ 深档 39–48s
- 工程细节：`-ngl 99` 全层卸载、`--jinja` 思考档位、`--cache-reuse 256` 同卷多问免重算
- 如实说明：深档 40s 是 4B 在 8GB 消费级显卡上的物理上限，已用流式缓解体感
role: supporting

### P9｜模型核心贡献：消融实验（20 分）
- 矩阵：{1.7B, 4B} × {开思考, 关思考}
- **关键发现**：1.7B 开思考会"想不停"——思考 5027 字耗尽预算，正式回答 0 字
  → 这是"深档必须用 4B"的直接实验证据（不是主观选择）
- 结论：小模型不适合长思考档；双模型分工是端侧的最优解
role: hero（消融证据表 + 巨型数字对比）

### P10｜端到端闭环 + 工程质量
- 闭环：导入 → 解析 → 整卷装载 → 三档生成 → 流式展示 → 溯源校验
- 工程质量：模块化 6 模块、一键启动脚本、智能降级兜底、异常处理
- 测试资产：3 份含考核点合同 PDF（7 个考核点全部可定位）、消融脚本、出图脚本
role: supporting
